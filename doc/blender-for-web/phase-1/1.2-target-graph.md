This large SCC is a structural characteristic of Blender's current CMake target layout. It is **not** evidence that a cube constructor needs all 19 modules at runtime. ## B. Public vs private link boundaries

The \`blender_link_libraries\` helper in \`build_files/cmake/macros.cmake\` defaults unmarked links to \`PRIVATE\`; this matters when interpreting an unqualified dependency.

Public edges explicitly seen in the source:

- BLI publishes DNA, internal Profile, fmt, optional TBB and OpenImageIO.
- BKE publishes internal Profile and optional OpenVDB. Source comment says OpenVDB types occur in public headers.
- Blender Loader publishes \`bf::blenloader_core\`.
- GPU additionally publishes generated shader libraries: compositor, draw, GPU and image-buffer OpenColorIO shaders.

CMake's \`PUBLIC\` edges can propagate dependencies through consumers even when a selected runtime function doesn't call those subsystems.

## C. Conditional and platform link buckets

| Group | Concrete CMake condition | Source-level implication |
| --- | --- | --- |
| GHOST desktop platform | \`WITH_GHOST_X11\`, \`WITH_GHOST_WAYLAND\`, SDL, WIN32, APPLE | Window/event implementations require platform-specific libraries |
| GHOST headless | \`WITH_HEADLESS\` | Bypasses normal desktop window selection but does not create browser window services |
| GPU OpenGL | \`WITH_OPENGL_BACKEND\` | Adds OpenGL backend sources and Epoxy |
| GPU Vulkan | \`WITH_VULKAN_BACKEND\` | Adds Vulkan backend sources, shaderc, Volk and memory allocator |
| GPU Metal | \`WITH_METAL_BACKEND\` on Apple | Includes Objective-C++ Metal backend |
| BKE Python | \`WITH_PYTHON\` | Adds Python and Python-BMesh library dependencies |
| BKE fluid/physics | \`WITH_MOD_FLUID\`, \`WITH_BULLET\`, \`WITH_MOD_OCEANSIM\` | Adds sim libraries and flags; not every BKE target edge disappears |
| Geometry Boolean | \`WITH_MANIFOLD\`, optional GMP | Selected geometry algorithms use third-party precision/Boolean support |
| Geometry UV | \`WITH_UV_SLIM\` | Adds UV solver include path/defines |
| Build/test | \`WITH_GTESTS\` and GPU test flags | Additional test targets (not production runtime) |

Some optional-target aliases appear even when a feature is disabled; an empty or stub alias is not proof that the third-party library was linked. Evaluate in a *configured build* before removal decisions.

## D. Source vs build-time generators (verified exact outputs)

### MakesDNA

\`source/blender/makesdna/intern/CMakeLists.txt\` builds the **native host executable** \`makesdna\`. Its command generates:

- \`dna.cc\`
- \`dna_defaults.cc\`
- \`dna_struct_ids.cc\`
- \`dna_type_offsets.h\`
- \`dna_verify.cc\`

These outputs feed \`bf_dna\`, DNA defaults and generated structural metadata. In a WebAssembly cross-build, the generator is a **host tool**; do not assume it can be executed as WASM during the build.

### MakesRNA

\`source/blender/makesrna/intern/CMakeLists.txt\` builds **\`makesrna\`**, which produces \`rna_*_gen.cc\` from DNA/RNA definitions and builds \`bf_rna\`. BKE explicitly declares a build dependency on \`bf_rna\`. Again, the generator and generated runtime code have different build/host roles.

### GPU shader metadata

\`source/blender/gpu/CMakeLists.txt\` uses \`file(GENERATE ...)\` for shader-source list, metadata and info headers and publicly links generated shader libraries. The GPU code path is not a cheap standalone subset merely because the native renderer is not needed.

**Phase 1.3 implication:** Cross-compiling with Emscripten needs host-native generator stages and verified generated include paths. A successful native configuration must precede any claims about stripping all of DNA/RNA or GPU.

## E. External dependencies for the selected target graph

- **Core C/C++:** guardedalloc, intern atomic, logging, formatting, Eigen, DNA, TBB where parallel code uses it.
- **BLI:** JSON/xxhash/wcwidth, zlib/zstd, optional GMP/FFTW, OpenImageIO public interface.
- **BKE:** FreeType, optional OpenVDB, OpenSubdiv, audio, and many application subsystem libraries; exact used feature matters.
- **Geometry:** Curve Fit, optional GMP/Manifold and optional UV SLIM includes.
- **GPU/GHOST:** platform GL, Vulkan or Metal dependencies, native input/OS services.
- **Image Buffers:** OpenImageIO/OpenEXR, JPEG, OpenColorIO and conditional codecs.

These are target-level inventory categories. For the first cuboid and discrete extrusion seeds, see [source closure](1.2-source-closure.md). Compile-time and link-time proof is assigned to Phase 1.3.

## F. Reproducible graph commands

Static analysis (no configured compilation required):

\`\`\`sh
python3 tools/blender_web/dependencies/audit_static.py \
  --root . --out build/blender_web/dependency-audit.json
\`\`\`

Configuration-aware CMake graph (requires platform dependencies and full native checkout):

\`\`\`sh
cmake -S . -B build/web-dependency-native -G Ninja
cmake --graphviz=build/web-dependency-native/targets.dot build/web-dependency-native
\`\`\`

The second command requires a **successful configure**, and is a recommended Phase 1.3 diagnostic—not a test claimed to have run here. Note that the static script conservatively includes conditionally declared edges.
