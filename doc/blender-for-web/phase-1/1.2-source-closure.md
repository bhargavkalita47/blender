This is a *source call trace*, not an exact set of compilable object files. Include lists do not resolve references at the object-file level.

## BMesh discrete-face extrusion

Principal sources and symbols:
- bmesh/bmesh.hh documents face-corner loops and nested BMesh operator slots.
- bmesh/intern/bmesh_mesh.cc: BM_mesh_create (line 128), BM_mesh_data_free and BM_mesh_free (line 264).
- bmesh/intern/bmesh_operators.cc: BMO slots, nested operation infrastructure and cleanup.
- bmesh/intern/bmesh_opdefines.cc: extrude_discrete_faces registered at ~1368, executing bmo_extrude_discrete_faces_exec.
- bmesh/operators/bmo_extrude.cc: bmo_extrude_discrete_faces_exec at line 42.

Direct includes of bmo_extrude.cc: MEM_guardedalloc.h, DNA_meshdata_types.h, BLI_math_geom_c.hh, BLI_math_vector_c.hh, BLI_vector.hh, BKE_customdata.hh, bmesh.hh, intern/bmesh_operators_private.hh.

Observed execution:

    BMesh + selected BMFace inputs
      -> BMesh operator "extrude_discrete_faces" / slot "faces"
      -> bmo_extrude_discrete_faces_exec
          -> BMO_slot_bool_get(... "use_select_history")
          -> BMO_ITER(... "faces", BM_FACE)
          -> BMO_face_flag_enable(original, EXT_DEL)
          -> BM_face_copy(... copy attributes)
          -> BMO_face_flag_enable(new face, EXT_KEEP)
          -> BM_elem_attrs_copy / BM_face_create_quad_tri on each boundary
          -> optional selection history BLI_ghash mapping
          -> BMO_op_callf("delete geom=%ff context=%i") [nested operation]
          -> BMO_slot_buffer_from_enabled_flag("faces.out")
      -> caller translates new vertices and updates normals

The nested DELETE operator makes an isolated bmo_extrude.cc-only link unrealistic.
Required source families include BMesh topology, BMesh operator registration and dispatch,
BKE CustomData, BLI memory/hash/vector/math, allocator/mempools, DNA, and normal recalculation.

Other caveat: bmesh_mesh.cc BM_mesh_free includes optional Python BMesh-handle invalidation
when py_handle is nonnull. Even if the web editor never uses that branch at runtime, a
full translation unit may still require symbol resolution until separated/guarded.

## What is and isn't proven

Proven by inspected source: precise direct includes, public entry declarations, selected
call chains, registration names, major allocation/attribute mechanisms, and target
declarations. Not proven: source-file-level transitive C++ symbol closure, working separate
core linkage, native fixture outputs, or WebAssembly behavior.

Static analyzer supplied in tools/blender_web/dependencies/audit_static.py to enumerate
internal target edges, source include closure, ambiguous includes and SCCs on a full checkout.
It does NOT prove CMake condition evaluation, symbols, generated headers or buildability.
