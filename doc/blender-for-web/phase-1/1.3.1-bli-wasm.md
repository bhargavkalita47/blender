# Phase 1.3.1 — Genuine Blender BLI WebAssembly smoke test

**Status:** Automated Emscripten build and runtime test being verified in GitHub Actions.
**Blender source baseline:** 5.4 Alpha, `67e5a5f874cf37e2a114cebd24f219d8c44a16ad`.
**Working branch:** `dev/p1-feasibility`. Original `main` remains untouched.

## Hypothesis

We can compile an existing Blender C++ implementation file directly to WebAssembly, link it to a small explicit C ABI, and call that module from JavaScript without bringing in Blender's desktop application, GHOST, GPU, the native UI, OpenColorIO, DNA generators, or BMesh.

This is the **first portability proof**, not an independent modeling engine or a complete browser 3D application.

## What is built

- **Original Blender implementation:** `source/blender/blenlib/intern/math_base.cc` from the pinned fork. This file implements integer powers, precision-controlled rounding, and decimal power-of-10 helpers.
- **Thin C ABI wrapper:** `tools/blender_web/wasm/bli_math_bridge.cc`. Calls `blender::pow_i`, `double_round`, `floor_power_of_10`, `ceil_power_of_10` without reimplementing them.
- **Build:** `tools/blender_web/wasm/build-bli-smoke.sh`, invoking Emscripten `em++` with C++20 and optimization. Output `bli_smoke.wasm` and an ES-module JavaScript factory `bli_smoke.mjs`.
- **Runtime verifier:** `tools/blender_web/wasm/verify-bli-smoke.mjs`. Confirms actual WASM magic bytes, exported binding availability, integer powers, round-half-even behavior and powers of 10.
- **CI:** `.github/workflows/blender-web-p1-3-1-bli-wasm.yml` installs **pinned Emscripten 4.0.12** and runs compilation/test on a Linux GitHub runner.

This intentionally requires only BLI source files and the Emscripten standard library. Browser rendering, pointer handling and BMesh come later.

## Reproduce outside CI

Install/activate [emsdk](https://github.com/emscripten-core/emsdk) version 4.0.12 and source `emsdk_env.sh`. Then from the repository root:

```sh
bash tools/blender_web/wasm/build-bli-smoke.sh
node tools/blender_web/wasm/verify-bli-smoke.mjs build/blender_web/wasm
```

The Emscripten toolchain makes `.wasm` and `.mjs`. The Node.js verifier exercises real WASM exports via the ES module loader. The build uses `-sENVIRONMENT=web,node`, so its generated loader is intended for both environments, but **this step does not run a browser test**.

## Acceptance criteria

- [ ] Emscripten installs reproducibly at a pinned version in CI.
- [ ] The original unmodified BLI `math_base.cc` compiles and links under `em++`.
- [ ] The output is a genuine non-empty WebAssembly module with an ES-module loader.
- [ ] JavaScript loads the module and successfully evaluates real Blender math functions.
- [ ] CI uploads the compiled `.wasm`, loader and build provenance.
- [ ] The web integration branch receives this proof only after successful CI.

## Explicit limitations

- No BMesh or persistent Mesh structures compiled: these require broader BKE/CustomData/DNA closure (Phase 1.3.2).
- No browser canvas, renderer, scene or mesh buffer interchange: later milestones.
- No native OpenColorIO or Blender full-CMake build: original Phase 1.2 native linker verification remains outstanding.
- This test only establishes portability of one real BLI source unit, not the entire Blender geometry kernel.
- The wrapper rejects negative and extreme exponent values as a simple API guard; Blender's math implementation itself is unchanged.
