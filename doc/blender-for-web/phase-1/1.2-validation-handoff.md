# Phase 1.2 — Closure verification and Phase 1.3 handoff

**Status:** Static architecture and source evidence documented. Dynamic link verification needs a configured checkout and has NOT been executed.

## Definition of complete build closure

For an independent native modeling target, dependency closure means: pinned source revision; compiler configuration; required translation units; preprocessed headers; generated files and host generator programs; complete definitions for undefined symbols; global initializers; third-party libraries; OS and threading requirements; and successful runtime tests.

CMake target dependencies and raw source includes are insufficient to prove independent linkage.

## Seed A — Cuboid creation

Source: source/blender/geometry/intern/mesh_primitive_cuboid.cc. Candidate core includes BKE Mesh and ID allocation, attributes/custom data, edge calculation, BLI math/containers, guardedalloc, and DNA.

Expected baseline when testing an unsubdivided cube: 8 vertices, 12 edges, 6 quad faces and, with UV enabled, 24 face corners. Verify bounds, normals, attributes and cleanup.

The source itself includes BKE attributes and Mesh. Its BKE allocation path reaches the broader ID system, even without UI interaction. The exact object-file subset requires linker evidence.

## Seed B — BMesh discrete-face extrusion

Source: source/blender/bmesh/operators/bmo_extrude.cc, entry bmo_extrude_discrete_faces_exec. Candidate core includes BMesh allocation, topology, construction, selection history and BMO operator registration/dispatch; nested delete operator; BKE custom data; BLI hash/vector/math; allocator and DNA.

The registered BMesh operator table can reference many other operator functions. Symbol resolution needs to show whether extracting a narrow set still requires that table or a smaller new registry. The latter would constitute code refactoring in Phase 2.

Verify correct topology, proper per-corner attributes, deterministic output and destruction without leaks.

## Build investigation commands

Run in the full Blender checkout with required native toolchain/dependency bundle:

    python3 tools/blender_web/dependencies/audit_static.py --root . --out build/blender_web/dependency-audit.json

    cmake -S . -B build/web-native-audit -G Ninja -DCMAKE_EXPORT_COMPILE_COMMANDS=ON

    cmake --graphviz=build/web-native-audit/targets.dot build/web-native-audit

    cmake --build build/web-native-audit --target blender

Find each seed in build/web-native-audit/compile_commands.json and inspect object undefined symbols with nm -C or the platform equivalent. Record the link closure and create a minimal, separately linkable target. Use native fixtures and sanitizers to verify behavior.

These commands are specified for execution, not claimed as executed. Toolchain paths, CMake flags and dependency bundles vary by OS.

## Generated build artifacts

- Host makesdna executable creates dna.cc, dna_defaults.cc, dna_struct_ids.cc, dna_type_offsets.h and dna_verify.cc.
- Host makesrna executable creates generated rna_*_gen.cc sources. BKE depends on the bf_rna target.
- GPU CMake generates shader source/metadata/info list headers and links generated shader libraries.
- Generators executed during an Emscripten cross-build must run on the build host; compiling their target executables to WASM cannot be assumed to work.

## Native-to-browser risk inventory

| Source system | Verified dependency | Recommended adaptation |
| --- | --- | --- |
| BKE app directory | GHOST_ISystemPaths dispose in blenkernel/intern/appdir.cc | Separate platform service |
| GPU context | GHOST headers inside gpu/intern/gpu_context.cc | Avoid GPU context in CPU geometry WASM target |
| GHOST selector | Win32/Cocoa/X11/Wayland/SDL native implementations | Replace with browser event/canvas boundary |
| Mesh conversion | BKE attributes, shape keys, multires, DEG inside bmesh_mesh_convert.cc | Start with simple BMesh operations, add full conversion later |
| Boolean | BKE/BMesh and optional numeric geometry libs | Defer complex Boolean until core tested |
| Mesh edge calc | BLI task/threading included | First test single-thread and determine thread requirements |
| File save | WM -> BLO_write_file -> DNA data model | Separate from the primitive/extrude core experiment |

## Phase boundary

Static target relationships, known generators, architecture cycles, initial source calls, third-party categories and native/browser blockers are mapped. The procedure to get an exact, configuration-resolved linker closure is recorded.

**Not verified:** full real CMake graph, preprocessor-dependent header set, all linker definitions, minimal object-file list, native executable build, WebAssembly executable.

Phase 1.3 feasibility must deliver those observed build results before Phase 2 code stripping can be considered safe. Analysis documents and the audit script change no native Blender engine source.
