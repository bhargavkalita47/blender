# Phase 2.3 — Native modeling-core stabilization

**Status:** Acceptance plan created, **no tests executed**. Subphase cannot be signed off before a separately linked engine exists.

## Test layers

### A. Native Blender reference — required

Execute the source-pinned `tools/blender_web/tests/native_reference.py` using Blender 5.4 Alpha in background mode. It validates basic cube topology, assigns UV custom data, runs a native BMesh extrusion and triangulates output.

Pass: correct version, no Python assertions or error exit, emitted reference JSON is preserved with build provenance. This test alone does **not** validate the extracted core.

### B. Reduced core and reference parity — blocked

Once Phase 2.2 provides an independently linked native modeling library, write equivalent tests through its *public engine API*:

- Build the same cube: 8 vertices, 12 edges, 6 quad faces.
- Assign UV coordinates to loops and verify post-operation preservation.
- Extrude a top face and verify final geometry is finite, non-degenerate, topologically consistent and matches the recorded native behavior.
- Triangulate and verify exact triangle counts and valid indices.
- Run the same operations on multiple disconnected objects and check object lifetime.
- Export vertex/index/UV buffers and compare positions with epsilon tolerance, rather than only byte-level hashes.

Pass: outputs match the native reference within declared tolerances. No comparison test can be legitimately marked passed before the extracted core runs.

### C. Memory, lifetime and deterministic results — blocked

- Repeat create, topology edit, snapshot and destroy at least 1,000 times under an address/leak sanitizer in the native build.
- Reject use-after-destroy, invalid handle, out-of-range element and invalid scene/object references gracefully.
- Verify that buffer snapshots remain valid for their documented lifetime.
- Test topology mutation after snapshots are requested.
- Test both debug and optimized configurations; log compiler/toolchain and allocation settings.

### D. Build isolation and original-source regression — blocked

- Confirm the reduced target has no unresolved symbols and no runtime dependency on native GHOST/Draw/GPU unless explicitly justified.
- Generate a target graph (`cmake --graphviz=...`) and inspect symbols/link flags.
- Build the original native Blender application with the extraction mode disabled.
- Confirm Blender's upstream source directories, modules, licenses and build defaults were not deleted or silently overwritten.
- Pin source baseline; document every disabled optional library and changed compile definition.

### E. WebAssembly feasibility — next phase boundary

Native stabilization should not be confused with Emscripten compatibility. Phase 1.3 has now verified isolated genuine Blender BMesh WASM in Chromium, Firefox, and WebKit. Phase 2.2's initial standalone native BMesh fixture also passed its independent CI build and smoke test, but broader native source-pinned reference parity, UV behavior, sanitizer checks, and complete Phase 2.3 stabilization remain open. Phase 3.1 is the production browser integration.
