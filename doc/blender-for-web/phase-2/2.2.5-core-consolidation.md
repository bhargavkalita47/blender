# Phase 2.2.5 — Modeling core consolidation and shipping contract

**Status:** Initiated; architecture and acceptance plan only, implementation pending.
**Branch:** `dev/p2-core-consolidation`, stacked on `dev/p2-attributes-uv`.
**Pinned source:** `67e5a5f874cf37e2a114cebd24f219d8c44a16ad`.

## Scope
1. Audit the 2.2.3/2.2.4 C ABI and replace fixture-specific entry points with versioned, documented capabilities and error codes; maintain a compatibility bridge while migrating tests.
2. Define engine instance, mesh, element, selection, attribute, and export-buffer lifetime and ownership. Reject stale IDs and invalid states; ensure failed operations are atomic where feasible.
3. Unify native and Emscripten builds with pinned source manifests, deterministic flags, provenance and reproducible CI artifacts. Keep original Blender files unmodified.
4. Audit source and runtime dependencies for desktop/GPU/window-manager leaks and undefined symbols. Measure wasm startup size, edit throughput, peak memory, and multi-mesh isolation.
5. Add robust negative/degenerate/non-manifold fixtures, sanitizer jobs (ASan/UBSan for native), repeated lifecycle tests, and browser integration regression across Chromium, Firefox and WebKit.
6. Produce a minimal consumer integration sample showing create/edit/export/destroy and typed-array transfer; distinguish this engine sample from a complete 3D editor or viewport.

## Acceptance gates
- All pinned-reference geometry and attribute/UV parity suites from 2.2.3 and 2.2.4 pass.
- Stable documented public ABI, memory ownership rules, version negotiation and error behavior.
- Native and wasm32 CI pass; sanitizer and browser matrix pass with captured artifacts.
- No net tracked allocation leaks, no cross-mesh corruption, no stale-handle access, and bounded WASM memory growth over repeat cycles.
- No renderer/window-manager dependency in extracted core. No claims about a full upstream desktop Blender build.
- Review completed and stacked PRs integrated only after all required checks are green.

## Dependencies
This branch intentionally stacks on incomplete 2.2.3 and 2.2.4 work. It is a kickoff checkpoint, **not** evidence that Phase 2.2.5 has been implemented or verified. Phase 2.3 remains the subsequent stabilization and original-application regression milestone.
