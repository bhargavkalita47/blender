# Phase 2.2 — Native reduction and extraction experiment

**Status: incomplete; build validation pending.**
**Starting point:** Blender 5.4 Alpha, pinned SHA `67e5a5f874cf37e2a114cebd24f219d8c44a16ad`.

## What has been changed

The phase 2 branch `dev/p2-extraction` introduces two *opt-in* test assets and does **not** modify, delete, or replace Blender's upstream geometry implementation:

1. `tools/blender_web/cmake/modeling-headless.cmake` — a reversible CMake cache profile that turns off selected non-modeling functions for a native headless diagnostic build; retains Python and topology-supporting GMP, Manifold, OpenSubdiv and UV solver options.
2. `tools/blender_web/tests/native_reference.py` — executes real Blender BMesh cube creation, custom UV assignment, face extrusion and triangulation and emits reference topology metrics.

**These do not yet constitute an independently linked extracted modeling core.** They establish safe build/configuration and regression inputs for doing so.

## Reproduce the diagnostic experiment

Prerequisites: a full checkout of the pinned Blender fork (including its required submodules/dependencies and Blender's documented native toolchain).

```sh
# From repository root; configure in an out-of-tree build directory.
cmake -S . -B build/web-modeling -G Ninja \
  -C tools/blender_web/cmake/modeling-headless.cmake

# Diagnostic native build — intentionally still the upstream Blender target.
cmake --build build/web-modeling --target blender --parallel 4

# Native behavioral baseline, using the resulting Blender executable.
# The Blender binary location depends on the generator/platform:
./build/web-modeling/bin/blender \
  --background --factory-startup --threads 1 \
  --python-exit-code 1 \
  --python tools/blender_web/tests/native_reference.py
```

The build path above is illustrative; adjust the executable location according to the actual build output. Configure options require verifying compatibility with the user's local OS/dependency bundle. A successful profile build **does not** establish that GHOST, GPU or Blender Loader were fully removed from the linker graph.

**Not executed in the current environment:** the complete repository is not mounted here and the Blender executable is not installed. Therefore build/run results are unknown.

## Real extraction still required

| Slice | Primary sources | Dependency challenge | Initial gate |
| --- | --- | --- | --- |
| A. Math and allocation | BLI math/containers, guardedalloc, atomic | Header/source closure, generated configuration | Independently compile/link/test a tiny math target |
| B. Mesh model | BKE mesh/attributes/customdata, required DNA | BKE's broad target links, generated DNA/RNA | Create/free Mesh without desktop renderer |
| C. Editable topology | BMesh internals, operators, conversion | BMesh↔BKE cycles, DEG and editor wrappers | Create/edit/free a BMesh with native target |
| D. Geometry ops | Cuboid, selected extrude/bevel/triangulation | BKE/Nodes/Geometry target cycles | Reference-compatible geometry outputs |
| E. Headless C ABI | Opaque handles, buffer snapshot, error handling | Memory ownership, init/shutdown, stale pointers | Stable external API with repeated edit/destroy |
| F. Browser display boundary | CPU geometry buffer snapshot | GPU/Draw/GHOST entanglement | Extracted core's link closure has no native graphics dependency |

An extraction is considered **real** only after the selected source files produce a separate build target that compiles and links without pulling in the original full Blender application runtime. Disabling features in the existing native Blender binary is only a diagnostic step.

## Recommended separation strategy

- Preserve original source paths and license headers. Prototype a new opt-in core target rather than rewriting BMesh code.
- Start with the lowest dependency closure that exercises original Blender math/geometry functions; use build logs and symbol analysis to expand it.
- Do not adopt a substitute custom topology algorithm and then claim the engine has been ported from Blender.
- Record each new include/library requirement, generated header, platform service and global initializer.
- Keep `main` unchanged and do not merge untested C++ refactors to `blender-for-web`.
