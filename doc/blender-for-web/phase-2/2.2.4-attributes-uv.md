# Phase 2.2.4 — Blender BMesh attributes, UVs and mesh conversion

**Status:** Initiated; implementation and acceptance tests pending.
**Branch:** `dev/p2-attributes-uv`, stacked on `dev/p2-modeling-ops`.
**Pinned source:** `67e5a5f874cf37e2a114cebd24f219d8c44a16ad`.

## Scope and implementation order
1. Inventory the original Blender `CustomData` layer APIs and the existing extracted BMesh ABI. Record exact layer ownership, allocation, and copying semantics before adding public functions.
2. Expose creation, enumeration, read and write of per-vertex, per-edge, per-face and per-loop attributes, starting with the original Blender per-loop UV layer. Use opaque mesh/element handles and bounded copies; do not expose native pointers.
3. Preserve corner UVs and other supported layers through primitive creation, translate, extrude, poke, inset, subdivide, deletion and mesh conversion. Document unsupported operator/layer combinations explicitly.
4. Implement deterministic export of indexed vertex positions, polygon loop/corner indices, triangle indices, UVs and normals, including non-quad and concave faces using original Blender triangulation where available.
5. Define mesh conversion contracts and ownership for both native and wasm32 consumers, with explicit buffer release and stale-handle rejection.

## Acceptance gates (all required)
- Build and link original source units without GPU/GHOST/WM and without undefined symbols.
- Match Blender 5.4 Alpha at the pinned hash on UV seams, shared vertices with distinct corner UVs, n-gons, triangulation, normals and attribute values before/after topology mutations.
- Test invalid handles, missing layers, wrong domain/type, out-of-bounds indices, NaNs, degenerate faces, and unsupported topology without partial writes.
- Run repeated create/edit/export/free cycles with allocation baseline restored and concurrent mesh isolation preserved.
- Verify wasm32 transfer into independent JS typed arrays in Chromium, Firefox and WebKit after native acceptance.
- Store CI artifacts and comparison JSON; keep the PR draft until all gates pass.

## Dependencies and boundaries
Phase 2.2.3 operators are still in development; this branch is intentionally stacked and must be rebased as they stabilize. No claim of UV parity or a complete web viewport is made by this kickoff. The full upstream Blender/OpenColorIO desktop configuration issue is separate.
