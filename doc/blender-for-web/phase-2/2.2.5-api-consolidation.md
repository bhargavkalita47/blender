# Phase 2.2.5 — Modeling core and ABI consolidation (initiated)

**Status: EXPERIMENTAL / IN PROGRESS. Not a public stable ABI or shipping
core.** This draft stacks on 2.2.4 and 2.2.3 and leaves original `main` untouched.

**Pinned Blender 5.4 Alpha SHA:** `67e5a5f874cf37e2a114cebd24f219d8c44a16ad`

## Experimental contract, revision 1

`tools/blender_web/native_core/blender_web_api.h` is the first explicit
C-consumable boundary. A separately compiled C program
(`native_core_abi_contract.c`) links to the original-Blender C++ modeling
library and verifies the declared functions without exposing C++ headers,
pointers, BMesh structs or allocator ownership to client code.

Add opt-in native discovery exports:

- `web_mesh_api_revision()` returns 1. This is a **test revision**, NOT a
  stable ABI version or compatibility promise.
- `web_mesh_api_capabilities()` returns a bit mask describing which optional
  native functions are actually compiled. Consumers must check bits.
- `web_mesh_api_max_live_meshes()` reports the current constrained slot cap
  (16). Any future expansion needs explicit capacity and lifetime tests.

All returned mesh tokens are opaque generation-tagged integers. Successful
creation returns > 0; mutations normally return 0; buffer exports return an
element count; errors are negative. Details of negative values are
**function-specific at this stage**. Output buffers are caller-allocated, and
mesh data is copied rather than exposing internal Blender allocations.

The currently exported polygon geometry stream is NOT a final WebGL buffer
contract: arbitrary concave/nonplanar polygon triangulation and UV corner
mapping remain unresolved. Similarly, the in-process registry is not
thread-safe or reentrant, and handles are not persistent object IDs. Element
indices are iteration snapshots, not IDs stable across topology mutation.

## Initial native acceptance

`.github/workflows/blender-web-p2-2-5-abi.yml` must pass **actual** CI:

1. Build the original Blender source subset and independently compiled C
   client. CTest must execute both the existing C++ BMesh smoke and the new C
   API smoke. Keep linker `--no-undefined` and desktop-source isolation.
2. Verify opaque handles, stale-handle failure, bounded float/index copies,
   feature discovery, loop UV mutation and proper disposal.
3. Re-run 2.2.3 BMesh tests and 2.2.4 UV test, comparing against exact
   source-pinned official Blender reference. Preserve evidence artifacts.
4. Do not mark complete or merge a draft PR before checks and review.
