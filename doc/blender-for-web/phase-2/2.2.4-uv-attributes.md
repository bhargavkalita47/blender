# Phase 2.2.4 — UV and attribute extraction (experimental, initiated)

**Status: IN PROGRESS — no parity or production claim until the CI gate is green.**
**Source pin:** Blender 5.4 Alpha `67e5a5f874cf37e2a114cebd24f219d8c44a16ad`
**Branch:** `dev/p2-uv-attributes`; stacked on `dev/p2-modeling-ops`. No changes to `main`.

## First source-backed vertical slice

The opt-in native adapter exposes original Blender `BMesh::ldata` with
`BM_data_layer_add`, `CustomData_get_offset(CD_PROP_FLOAT2)`, and
`BM_ELEM_CD_GET_FLOAT2_P`. UV data is stored per **BMLoop face corner**, not
per BMVert. This supports different UV coordinates on corners that share a
3D vertex (required for seams) and does not implement a parallel fake UV map.

New exports (native-only while the WASM build remains unchanged):

- `web_mesh_uv_layer_ensure(handle)`: idempotently add first UV layer.
- `web_mesh_uv_float_count(handle)`: number of floats needed to copy a face-loop UV stream.
- `web_mesh_set_uv(handle, face_index, corner_index, u, v)`: write one corner, rejecting nonfinite data, missing UV layer and invalid indices.
- `web_mesh_copy_uvs(handle, output, float_capacity)`: copy corner UVs into caller memory in face iteration / loop winding order.

The boundary is still intentionally minimal: the per-corner stream does
**not** yet supply triangle-to-corner mapping, a stable face/loop ID, multiple
named UV layers, nor an attribute-preserving edit propagation guarantee. The
current convex fan geometry export is not a general Blender nonconvex-ngon
triangulator. These are exit requirements, not assumed capabilities.

## Acceptance gate for this slice

`.github/workflows/blender-web-p2-2-4-uv.yml` must:

1. Build the separately linked original Blender native BMesh core with the UV
   adapter enabled, preserving strict linker and source-isolation checks.
2. Run `verify_uv_attributes.py`: plane UV values, seam-capable cube corners,
   guard and buffer bounds, stale handles, nonfinite write rejection,
   idempotent layers, independence from translation, and 200 lifecycle cycles.
3. Run `uv_reference.py` in the official Blender 5.4 Alpha binary with
   **exact pinned build hash**, then compare values with
   `compare_uv_reference.py`. Save evidence on failure as well.
4. Keep PR draft until the actual workflow conclusion is confirmed green.
   Do not treat source presence or CMake configuration alone as success.
