## What was compared

The official Blender `bmesh` Python API independently creates a 2-unit cube, assigns a reference UV layer, extrudes its top face by 1.0, extrudes the resulting top by 0.5, and finally triangulates faces using Blender's `BEAUTY` method. It emits exact vertex locations, undirected geometric edges, oriented canonical face loops, Blender-computed face normals, per-face areas, loop and face counts, and full surface area.

The extracted native core runs the *same geometry sequence* using its original Blender C++ `BM_mesh_create` / `BM_face_create_verts` and `BMO_op_exec(\"extrude_discrete_faces\")` through the compiled C ABI. Python `ctypes` copies native vertex and quad-fan index buffers and builds independently canonicalized geometry; the test checks winding-derived face normals and areas, edge connectivity, positions, extrusion height, and a zero net tracked Blender allocation after destroying the mesh.

The comparator requires equal geometry (position tolerance `1e-4`), matching winding and face normals, all expected stage counts, and **equivalent directed-plane surface coverage** after triangulation. The original Blender `BEAUTY` diagonal may differ from a simple quad fan, so triangle-index equality is deliberately not claimed.

| Stage | Vertices | Edges | Faces | Loops | Triangles | Geometry parity |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| Original cube | 8 | 12 | 6 | 24 | 12 | PASS |
| First top-face extrusion (+1.0 Z) | 12 | 20 | 10 | 40 | 20 | PASS |
| Second top-face extrusion (+0.5 Z) | 16 | 28 | 14 | 56 | 28 | PASS |

The resulting Blender-triangulated reference and extracted quad-fan representation both contain **28** triangles with identical total area and orientation/plane area coverage. Vertex positions, sorted edge geometry, canonical quad face loops and face-normal/area values also matched for each pre-triangulation stage.

## Boundaries for 2.2.3 and 2.2.4

- This is **exact source-matched reference parity for the cube and two top-face extrusions**, not proof of parity for the full Blender modeling tool set.
- The extracted core currently supports **quad-only** geometry snapshots; arbitrary n-gons, real triangulation APIs, bevel/inset/subdivide, multiple primitives and large scenes remain for 2.2.3 and later.
- The original Blender reference successfully creates and assigns a UV layer, but the extracted core has **no UV layer API**, so **UV parity is explicitly not claimed**. This belongs to 2.2.4.
- The extracted core's face normals in this test are derived from exported **face winding** and checked against Blender's original face normals. Blender's full derived/custom normal infrastructure is not yet independently extracted.
- The separate Phase 2.3 sanitizer and broader memory stability gates are still open.

**Exit verdict for 2.2.2's defined geometric/reference contract: PASS. Phase 2.2 as a whole remains in progress.**
